# Build Brief — SEAM Structural Lookup Page

Hand this file, plus `runners/` and `results/`, to Claude CLI.

## Objective

A web page where a visitor selects a compound and sees the structural
perturbation result produced by the locked SEAM drug runtime, alongside
that compound's independently known clinical profile, with the
zero-loading control shown for every run.

## Non-negotiable constraints

1. **The lock hash must be displayed and verified.**
   `62c6aa75effef85b9039251fd7fd2dae7e11b676e861f71ac7892f33a1bd85e4`.
   `runners/withdrawn_five.py` asserts this and aborts on mismatch. The
   page must show the hash it ran against.
2. **Never render a result without its control.** Every compound card
   shows `control (λ=0) transitions: 0` beside the perturbed result. The
   control is what makes the result meaningful; hiding it makes the page
   an assertion instead of evidence.
3. **No cross-compound ranking anywhere in the UI.** No leaderboard, no
   sort by severity, no "most dangerous" list. `ANALYSIS_CONTRACT.md`
   line 25: ordering is within the current compound run only. Compounds
   are selected individually and displayed individually.
4. **No predictive or clinical language.** The page reports what the
   engine returned and what is independently documented. It does not say
   a compound "is dangerous", "would have been caught", or "should be
   withheld". Criticality is structural, not clinical guidance — carry
   that line from the v3.12 report header.
5. **Data is generated by the runner, not hand-authored.** The page reads
   `results/withdrawn_five.json`. Do not retype numbers into HTML.

## Data source

`runners/withdrawn_five.py <path-to-runtime>` emits
`results/withdrawn_five.json`:

```
lock_sha256, rows (5734), structures (420),
compounds[]: name, formula, mw, dose_mg_day, loading_mmol_day,
             status (withdrawn|marketed), known_effect,
             projection_sha256, control_transitions,
             rows_with_new_breaks, tiers{},
             target_rows, target_structures[]{new_breaks, relations,
                                              structure, criticality}
```

## Page structure

- **Header:** runtime name, lock sha256, row/structure counts, and the
  statement that every run is preceded by a λ=0 control.
- **Compound selector:** seven compounds, listed alphabetically or by
  formula. Not by result magnitude.
- **Compound panel,** per selection:
  - formula, MW, dose, loading λ = mg/MW, projection sha256
  - control: transitions at λ=0
  - perturbed: rows with new breaks, tier distribution
  - target structures table: new_breaks / relations, structure name,
    criticality
  - independently known clinical profile, labelled clearly as external
    documentation and not an engine output
- **Method note:** λ is a loading coordinate only — no absorption,
  bioavailability, clearance, protein binding or distribution volume.
  Quote `SIDER_CORE_ENGINEERING.md` directly.
- **Limitations panel,** verbatim from `record/MANIFEST.md` §"Known
  limitations". Do not abridge. The string-encoding issue, the absent
  `argmax S[C]`, the CRITICAL tier arithmetic, and the audit disposition
  all belong on the page.

## Reproduce-it-yourself section

Show the exact command and let the visitor verify:

```
python3 runners/withdrawn_five.py /path/to/SEAM_DRUG_STRUCTURAL_RUNTIME_LOCKED_v3_12
```

Include `record/SHA256SUMS.txt` and `record/PACKAGE_SEAL.txt` as
downloads so a visitor can confirm the package they have matches.

## What the page must not claim

The marketed comparators (famotidine, albuterol) also return cardiac
structure breaks — 38/703 and 41/703 against cisapride's 62/703. The
page must present these side by side within each compound's own panel
and must not assert that the engine distinguishes withdrawn from
marketed compounds. Establishing that would require a pre-registered
decision rule and a false-positive rate, neither of which exists yet.
State plainly: each compound's result is shown against its own control
and its own known profile; no discrimination claim is made.

## Suggested build

Single self-contained HTML file, no external dependencies beyond a
CDN-hosted font if desired. Data inlined at build time from the JSON, or
fetched from a sibling `withdrawn_five.json`. Keep it readable on a
phone. Plain typography; this is an evidence page, not a product page.
